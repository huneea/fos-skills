# 공부 후보 모으기와 다시 보기

코디네이터 세션에서 사용자가 뜻을 물은 개념을 하루 끝에 후보로 모으고, 공부할 가치가 있는지 다시 본 뒤 글로 쓰는 절차다.
설명이 대화에만 남으면 압축될 때 사라지고, 모아 두기만 하면 다시 볼 때마다 기준이 달라 같은 후보가 오간다.
글을 쓰는 스킬과 글이 놓일 저장소는 사용자마다 달라 오버레이가 정한다. 이 문서는 어느 저장소에서나 같은 자리와 형식, 기준만 소유한다.

## 후보 파일

후보는 `<orch 루트>/study/candidates.md` 한 파일의 Markdown 표 한 줄이 하나다. 경로는 `"$SKILL_DIR/bin/orch.ts" orch_paths study` 로 받는다.
표 머리는 `| 주제 | 질문 | 생긴 곳 | 참고 | 상태 |` 이다. 표 앞의 글(그 저장소가 정한 규칙 같은 것)은 명령이 읽지 않고 고칠 때도 그대로 둔다.

| 칸 | 담는 것 |
| --- | --- |
| 주제 | 일반 기술 개념의 이름. 같은 주제는 한 줄만 둔다 |
| 질문 | 사용자가 실제로 물은 것을 일반 질문으로 바꾼 것 |
| 생긴 곳 | 어떤 일을 하다 나왔는지 한 줄. 내부 맥락은 뺀다 |
| 참고 | 근거로 댈 공식 문서나 널리 알려진 글의 이름 |
| 상태 | `후보`, `리뷰함: <이유>`, `뺌: <이유>`, `글 씀: <글 경로>` 가운데 하나 |

**회사 이름, 서비스 이름, 내부 식별자, 대상자 정보는 적지 않는다.** 이 파일이 공개 글의 재료가 되므로, 적는 자리에서 일반 개념과 질문으로 바꾼다.

행은 명령으로 고친다. 칸 안의 `|` 나 줄바꿈 하나로 표가 깨지기 때문이다. 명령의 옵션과 출력은 `--help` 가 소유한다.

```bash
"$SKILL_DIR/bin/orch.ts" study-candidates list --open
```

## 모으기

**사용자가 하루 끝 정리를 요청하면 그날 대화에서 사용자가 뜻을 물은 개념을 후보로 보여 주고, 고른 것만 적는다.** 고르지 않은 것은 적지 않는다.
기본값은 사용자가 요청할 때만 모으는 것이다. 코디네이터가 먼저 물을지, 어떤 말로 물을지는 오버레이의 「공부 후보」 칸이 정한다.
압축된 대화에서 그날 개념을 다시 찾을 수 없으면 남은 대화에서 찾은 것만 보여 주고, 빠졌을 수 있다고 함께 말한다.

```bash
"$SKILL_DIR/bin/orch.ts" study-candidates add --topic "$TOPIC" --question "$QUESTION" --origin "$ORIGIN" --ref "$REF"
```

`$TOPIC`, `$QUESTION`, `$ORIGIN`, `$REF` 는 위 표의 네 칸이다. 같은 주제가 이미 있으면 명령이 더하지 않고 종료 코드 1 로 끝난다.

## 주기

**`orch-doctor` 가 `STUDY-OPEN <개수> <파일>` 을 내면 그 개수와 파일을 사용자에게 한 줄로 알린다.** 스킬을 열 때마다 doctor 가 상태가 `후보` 나 `리뷰함` 인 줄을 센다.
언제 다시 볼지는 사용자가 정한다. 무엇을 공부할지는 사용자의 결정이라, 코디네이터가 알린 자리에서 상태를 바꾸지 않는다.
`리뷰함` 도 열린 후보로 센다. 공부할 가치가 있다고 정해 두고 글을 쓰지 않으면 같은 개념을 다음에 또 물게 된다.

## 다시 보기

사용자가 다시 보자고 하면 후보마다 아래 세 기준으로 판정안을 만들어 근거와 함께 보이고, 사용자가 확인한 것만 상태를 바꾼다.

- **다시 나올 만하다:** 다음 일에서 같은 질문이 다시 나올 만하다. 그날 그 일에만 있던 사정이 아니다
- **근거를 댈 수 있다:** 공식 문서나 널리 알려진 글로 설명의 근거를 댈 수 있다
- **이미 쓴 글이 없다:** 글이 놓일 저장소에 같은 주제의 글이 없다. 있으면 그 글을 고칠 거리로 보고 뺀다

| 바꿀 상태 | 조건 |
| --- | --- |
| `후보` → `리뷰함` | 세 기준을 모두 채운다. 이유에 어느 기준을 어떻게 채웠는지 적는다 |
| `후보` → `뺌`, `리뷰함` → `뺌` | 기준 가운데 하나라도 채우지 못한다. 이유에 그 기준을 적는다 |
| `리뷰함` → `글 씀` | 글을 실제로 썼다. 메모에 글 경로를 적는다 |

```bash
"$SKILL_DIR/bin/orch.ts" study-candidates set --row "$ROW" --status 리뷰함 --note "$REASON"
```

`$ROW` 는 `list` 가 낸 번호, `$REASON` 은 이유나 글 경로다. 이 표에 없는 전이는 명령이 거부한다.

## 글 쓰기

`리뷰함` 인 후보는 오버레이가 정한 글쓰기 스킬로 쓴다. 오버레이에 글쓰기 스킬이 없으면 어느 스킬로 어디에 쓸지 사용자에게 묻고, 그 답을 오버레이에 적는다.
글을 쓰기 전에 후보 한 줄과 세 기준의 판정을 그 스킬에 넘긴다. 글의 범위와 공개 판단은 그 스킬이 소유한다.
